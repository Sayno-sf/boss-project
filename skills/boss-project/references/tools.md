# 工具接入

使用已连接的 BOSS MCP 工具。调用前读取宿主提供的实际输入 schema；工具名可能带宿主前缀，不猜测参数或伪造成功响应。当前工具均要求 `root`，填写已授权项目的绝对路径，不用插件目录代替业务项目目录。

| 工具 | 用途 |
|---|---|
| `boss_status` | 核对当前项目、持久角色聊天、阶段和待处理事项 |
| `boss_team_board` / `boss_task_trace` | 查团队勘定的任务范围、负责人、当前决定与事件、轮次、交接记录 |
| `boss_agreement` / `boss_review_pass` | 登记有出处的决定，或由本次原审查员分别记录需求与质量证据。完整流程见[协作操作](collaboration.md) |
| `boss_messages` | 查看实际消息与原始工作依据 |
| `boss_report_view` | 只读查看中文阶段报告与当前状态 |
| `boss_init` / `boss_bind` / `boss_stage` | 初始化项目、绑定已真实创建的角色聊天、开始获授权阶段；绑定本身不创建聊天 |
| `boss_assign` | 在阶段允许的范围内向已登记角色派发任务 |
| `boss_discuss` | 向对应角色发起解释或讨论；讨论本身不授权修改需求 |
| `boss_claim` / `boss_sent` / `boss_complete` | 领取待投递任务、记录真实发送轮次、记录真实完成回复 |
| `boss_uncertain` | 发送或执行状态不明时保留待核查状态，避免盲目重派 |
| `boss_close_dispatch` | 有宿主证据确认未发送或轮次已终止时，按失败或取消结案 |
| `boss_deliver` | 提交实际成果文件与验证依据，生成独立审查任务 |
| `boss_review` | 提交或处理当前版本相关的审查记录，以实际 schema 为准 |
| `boss_report` | 提交阶段报告，进入等待 BOSS 批复的状态 |

## 当前版本的聊天转交

由原经理聊天直接组织连续派工。经理的调度循环不进入员工共用的派工槽。队列负责登记和认领，经理用宿主工具完成实际转交。

1. 核对项目和已获授权的角色聊天；缺少角色时通过宿主创建真实持久聊天，再用 `boss_bind` 登记返回的真实 ID。已有角色优先续接。
2. `boss_assign` 或 `boss_discuss` 入队，有明确材料或模型时填写 `materials`（项目内路径和版本）及 `modelPlan`。用 `boss_claim` 领取任务。没有可派任务时，区分空队列和等待既有批次结案。
3. 核对目标原聊天是否空闲，通过宿主工具投递认领原文。保存实际发送结果和模型配置，取得真实轮次 ID 后用 `boss_sent` 登记。工具只返回聊天 ID 时，从原聊天核对新轮次。
4. 用宿主等待和读取工具观察该轮。`boss_complete` 保存实际完成原文及其出处。发送或运行结果未知时先用 `boss_uncertain` 并核对原聊天。证据确认未送达或已终止时用 `boss_close_dispatch` 结案。
5. 员工交付 `boss_deliver` 后，按同一转交流程发送自动生成的独立审查任务。用 `boss_review` 登记本次交付 ID、审查任务 ID、成果版本及已完成审查回执所用的同一原文地址。经理整合并提交 `boss_report` 后停下。

宿主读取结果被截断时继续读取所需部分，或者标明记录范围并保留原聊天入口，不把截断摘要宣称为完整原文。用户在其他角色聊天中的新指令也需要带来源同步，不能伪装成经理或系统消息。

CLI 的真实入口是插件根目录下的 `src/cli.mjs`。从插件目录执行 `node src/cli.mjs --help` 获取本机支持的命令；在其他工作目录使用入口的绝对路径。不要把演示数据当真实项目状态，也不要绕过拒绝派工的结果改用其他入口继续开发。

本文件描述语义，不替代正在运行版本的 schema。缺少工具时检查插件连接并报告缺口，不假装已完成派工、批准或消息投递。使用 Codex 宿主的聊天工具时，遵守相同的项目授权、身份绑定和阶段规则。

用户批复由 CLI 的 `decide` 入口记录，MCP 不暴露批准工具。执行前必须确有用户的明确决定与意见，保留用户原话位置，并绑定报告 ID 和成果版本。接受未解决阻断时逐项记录接受范围；普通员工的完成通知不能作为 BOSS 批复。CLI 隔离是接口分工，不代表同一系统用户的其他终端无法调用它。

Windows 上使用 PATH 中的 `pwsh`，不运行 `powershell.exe`。命令行程序如 `node`、`python`、`git` 可直接执行。不要调用上游 autoloop 的旧 Windows 启动器；使用本插件已验证的接入实现。
