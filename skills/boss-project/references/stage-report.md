# 阶段报告

写给需要作判断的人。先讲成果和限制，再给可展开查证的依据；技术名称只有影响决策时才解释。经理整合结论并承担交付责任，不把员工的局部完成当整体完成。

主报告保留这些实质内容，空项可省略：

- 阶段名称及对应成果版本；当前审查结论。
- 已完成：用户现在能完成什么操作。
- 验证：实际做过哪些检查、结果如何；区分自动检查、真实运行和用户验收。
- 未完成或限制：会怎样影响使用；不能藏在附件。
- 下一阶段建议：可验证目标及需要改变的范围。
- 需要 BOSS 决定：具体取舍、影响和推荐项。
- 工作依据：员工工作报告、审查原文与未解决项、实际消息及验证记录的入口。

例如“提交的内容可以保存，关闭后重新打开仍能看到；多人同时操作尚未验证”比“持久化链路验收完成”更有判断价值。

正式提交后，标明等待批复并停止新的开发派工。解读报告可以继续。收到批复时记录决定、意见及关联版本，不将其压缩成没有条件的“已批准”。

受阻报告同样给出已完成成果、具体阻断、现有证据、可选路径与经理建议。不能要求用户代替团队排错，不能把尚未运行说成验证失败，也不能把没有证据说成已通过。
